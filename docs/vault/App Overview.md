# App Overview

Daily scrape of the Singapore car market, filtered and costed, published on the car website (port 8786). The website is the only output; the Telegram bot was retired on 2026-10-17 (see [[Changelog]]).

* Entry point in the container: `scheduler.py` supervises `main.py` (daily at 08:00 SGT, as a child process with a time limit, retried on failure), starts `coe_watch.py` on COE result days (`coe.results_watch`), runs `news_watch.py` a few times a day and `bid_capture.py` while bidding is open, writes `data/heartbeat` for the healthcheck, and after a second failure starts `heal.py`, which repairs `scrapers/` through `claude -p` and keeps the change only if the tests pass and the sections recover. Exit code 2 from `main.py` means only the site data write failed: retried, never repaired.
* Daily run: `main.py` runs `pipeline.py` `Pipeline.run(section)` (scrape and store: `run_fuel`, `run_coe` with backfill and forecasts, `run_used` with vault tracking and `mark_gone`, `run_new_ev`, `run_new_cars`, `run_official`), records `last_run_health` in `sent_state` (`date`, `section`, `dry_run`, `unavailable`; read by `scheduler.py` and `heal.py`), then `website.publish`. `--dry-run` scrapes and records the health without writing the site. Run status in the `runs` table: `ok`, `dry-run` or `site-failed`.
* Scrapers: `scrapers/coe.py` (Motorist first, LTA fallback), `scrapers/used_sgcarmart.py` and `scrapers/used_motorist.py` (Carro off), `scrapers/new_ev.py` (Sgcarmart electric car page), `scrapers/fuel_price.py` (Motorist grade board), `scrapers/registrations.py` (LTA M03 PDF, top selling brands). Each failure marks its section unavailable, the run continues. `scrapers/base.py` retries only transient errors (`_transient`, never a 403 block). `scrapers/used_common.py` skips sold cars, fills `{price_max}` and `{year_min}` in the search URLs from the filters, and calls the AI fallback only for fields the page does not label. `ai.py` turns AI off for the run after the first CLI failure.
* Website: `website.py` (`build`, `publish`) writes `data/site/data.json` atomically; `site/index.html` renders it (pages Today, New cars, Used cars, Brands, Bikes, Costs, Guide), served by the `car-site` nginx container on port 8786. New cars beyond EVs come from `scrapers/new_cars.py` (table `new_car_prices`). Brand website prices: `official.py` and `scrapers/official/` (table `official_prices`). Popularity ranking: `website.py` `Popularity`. Used car deal verdicts and red flags: `insights.py` (cache table `listing_flags`). Car photos on new car cards: `website.py` `car_image` (template `config.yaml` `site.car_image_url`). Alerts (watchlist, since your last visit): browser only, `site/index.html` alerts block. Official prices through the NAS Playwright server: `scrapers/base.py` `_browser_page`, `fetch_download`; robots override list `config.yaml` `official.playwright_robots_override`. Used car photos: `UsedListing.image_url`. News sources: `news_watch.py` with `sources.media_news_feeds`. 360° interior links: table `view360` (`db.py` `put_view360`), filled by `pipeline.py` `run_new_ev` and `run_new_cars`, read in `website.py` `build`. Settings: `config.yaml` `site`, `new_cars`, `official`.
* COE results the same afternoon: `coe_watch.py` polls from `coe.results_watch.start` until the new tender is out, then runs `Pipeline.run("coe")` and `website.publish`, and logs a vault event.
* News: `news_watch.py` reads LTA's RSS feed, keeps releases matching `news.keywords` (minus `news.exclude`), stores them newest first in `sent_state` key `news_items` (at most 30, each `title`, `link`, `published`, `summary`), and remembers seen links in `lta_news_seen`. `website.build` exposes them as `data["news"]`; the Today page shows up to 6 after the COE section.
* Failure alert: after every retry and repair, `scheduler.py` `_alert` records one alert a day as a vault event and in `sent_state` key `last_alert` (`{"at", "what"}`). Self repair attempts are logged to `logs/heal.log` (`heal.py` `notice`) and the vault, with records under `data/self_heal/`.
* Vault, movement log: `vault.py`, on when `VAULT_DIR` is set (`/vault` in the container, `/volume1/<USER>/Obsidian/SG Car Market` on the NAS). Writes `Activity/YYYY/MM/YYYY-MM-DD.md` (one note per day in a year/month folder; flat `Activity/YYYY-MM-DD.md` notes from before 2026-10-15 are moved there, never deleted, by `vault._ensure` on the first write, which `scheduler.py` `main` triggers at startup; one line per event, from `main.py`, `pipeline.py`, `coe_watch.py`, `news_watch.py`, `scheduler.py` and `heal.py`), `Cars/` (one note per used listing, price History) and `COE/` (one note per category). Every call is best effort.
* All filters and assumptions: `config.yaml`.

## Deployment

* Runs as the Dockge stack `sg-car-scraper` on the home NAS. Project folder is bind mounted at `/app`, so an update is copy files then Restart. A `requirements.txt` change needs a rebuild; a compose change needs Stop then Start.
* Website: `http://<nas>:8786` (home network or Tailscale). `RUN_ON_START` is "0": a full crawl takes about two hours and the scheduler catches up a missed day.
* Logs: `logs/run.log` in the stack folder.
* Vault: `/volume1/<USER>/Obsidian/SG Car Market`, mounted at `/vault` (compose sets `VAULT_DIR=/vault`, `.env` sets `VAULT_HOST_DIR=/volume1/<USER>/Obsidian/SG Car Market`). A compose change, so Stop then Start (or `docker compose up -d`).
